# Antigravity Session Token Metrics Guide

This reference explains how token usage is recorded in Antigravity conversation transcripts and how `session-tokens` computes session-level, turn-level, and step-level statistics.

---

## 1. Where Session Logs Live

Each Antigravity conversation session has a unique UUID (`<conversation-id>`) stored under:

```text
<appDataDir>/brain/<conversation-id>/.system_generated/logs/transcript.jsonl
```

On Windows, `<appDataDir>` defaults to `C:\Users\<user>\.gemini\antigravity`. On macOS/Linux, it defaults to `~/.gemini/antigravity`.

---

## 2. Core Token Fields in `transcript.jsonl`

Every line in `transcript.jsonl` is a JSON object representing a conversation step. Steps with `"source": "MODEL"` and `"type": "PLANNER_RESPONSE"` represent an LLM invocation and contain three token counters:

| Field in `transcript.jsonl` | Metric Name | Meaning |
| :--- | :--- | :--- |
| `input_tokens` | **Token In (Uncached)** | New or uncached input tokens processed by the model in that step. |
| `cache_read_tokens` | **Token Cache (Read)** | Previously processed context tokens served directly from the prompt cache in that step. |
| `output_tokens` | **Token Out (Generated)** | Tokens generated by the model in that step (includes internal reasoning/thinking, visible text, and tool call payloads). |

---

## 3. Derived Metrics & Formulas

For each `PLANNER_RESPONSE` step $i$:

1. **Step Prompt Context (`total_input_tokens`)**:
   $$\text{Prompt Context}_i = \text{input\_tokens}_i + \text{cache\_read\_tokens}_i$$
   This represents the **actual context window size** sent to the model on step $i$.

2. **Step Total Tokens (`step_total_tokens`)**:
   $$\text{Step Total}_i = \text{input\_tokens}_i + \text{cache\_read\_tokens}_i + \text{output\_tokens}_i$$

3. **Step Cache Hit Rate (`cache_hit_rate_pct`)**:
   $$\text{Cache Hit Rate}_i = \frac{\text{cache\_read\_tokens}_i}{\text{input\_tokens}_i + \text{cache\_read\_tokens}_i} \times 100\%$$

---

## 4. Cumulative Session Totals vs. Context Window Size

When analyzing a multi-step agentic session, it is important to distinguish between **Cumulative Session Totals** and **Current/Peak Context Window Size**:

- **Cumulative Token In (`sum(input_tokens)`)**: Total uncached input tokens billed/processed across all LLM calls in the session.
- **Cumulative Token Cache (`sum(cache_read_tokens)`)**: Total cached input tokens read across all LLM calls in the session.
- **Cumulative Token Out (`sum(output_tokens)`)**: Total tokens generated by the model across all LLM calls in the session.
- **Peak Context Window (`max(input_tokens + cache_read_tokens)`)**: The largest single-request prompt size reached during the session.
- **Current Context Window (`last(input_tokens + cache_read_tokens)`)**: The prompt context size as of the most recent model step.
- **Session Cache Hit Rate**:
  $$\text{Session Cache Hit Rate} = \frac{\sum \text{cache\_read\_tokens}}{\sum (\text{input\_tokens} + \text{cache\_read\_tokens})} \times 100\%$$

---

## 5. Turn-Level Attribution & Subagents

- **User Turns**: Each `"type": "USER_INPUT"` step marks the start of a new user turn. Grouping subsequent `PLANNER_RESPONSE` steps under their parent `USER_INPUT` reveals which user request consumed the most uncached input, cache reads, and output tokens.
- **Subagent Attribution**: When a session invokes subagents via `invoke_subagent`, the child subagent runs in its own `<subagent-conversation-id>` directory under `<appDataDir>/brain/`. The analyzer script detects subagent conversation IDs referenced in the parent transcript and optionally aggregates their token usage alongside the parent session.
